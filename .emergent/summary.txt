The goal is to enhance and stabilize the Dawa (teaching) and Prayer tracking functionalities of the ALSABQON application.

**Dawa/Azkar History Page ():**
1.  **Filtering:** History entries should be filterable to show only those created from the Prayer page (من الصلاة), manual entries, or all.
2.  **Navigation:** Prayer-linked entries must be clickable, navigating the user to the specific Prayer and Rakka where the entry was created.
3.  **Inline Editing:** Users must be able to edit the count and notes/comments directly within the history list without being redirected. Clicking editable fields should not trigger navigation.
4.  **UI Cleanup:** Remove any duplicate text or redundant information in the history entries display.

**Prayer Page ():**
1.  **Entry Creation:** When a user documents teaching activity (Dawa) within a prayer's Rakka, a corresponding entry must be created. Each Rakka (e.g., Rakka 1, Rakka 2) must generate a separate, distinct record. These records should not be merged.
2.  **Duplicate Prevention:** Submitting Dawa data multiple times for the same Rakka should update the existing record, not create duplicates. The submission button should be disabled during processing.
3.  **Data Persistence & Synchronization:** Notes and counts entered on the Prayer page for a Rakka must be saved. When a user edits a record on the Dawa History page, the changes (both count and notes) must be reflected when they return to the Prayer page, and vice-versa.
4.  **UI Polish:** Remove the No verses selected yet placeholder box from the prayer UI, while keeping the verse selection functionality intact.
